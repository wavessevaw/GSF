# Испытания Steam Deck OLED: 0.1.13 Experimental

Аппаратных измерений в облачной среде нет. Этот протокол поставляется по просьбе
пользователя вместо удалённого прогона. Он не подтверждает достижение цели.

1. Сохранить рабочую стабильную версию и исходные параметры запуска игры.
   Установить экспериментальный ZIP отдельно через Decky Loader. Проверить
   SHA256 архива и совпадение source commit в панели с BUILD_INFO.json.
2. Выставить штатными настройками SteamOS 90 Гц, GPU Clock AUTO, сначала 15 Вт,
   затем 10 Вт. GSF не меняет эти настройки. Отключить другие генераторы кадров.
3. Записать baseline без GSF на одной повторяемой сцене минимум 60 секунд после
   прогрева: source frametime/FPS, CPU/GPU utilization, GPU clock, APU/GPU power,
   TDP, температуры и фактическую частоту экрана. Отдельно записать поворот камеры,
   горизонтальное/вертикальное движение, объекты, HUD и scene cut.
4. Повторить для GPU LMC, ECO45, Flow Lite 1.0 и Flow Lite 2.0, при x2/x3/x4,
   не меняя сцену, лимит игры и качество графики. Для Flow Lite 2.0 отдельно
   сравнить последовательную и batched reconstruction. Порядок прогонов чередовать.
5. Основные точки: 45→90 x2, 30→90 x3, 22.5→90 x4. Затем 30 x4, 45 x3/x4
   на 90 Гц: число вычисленных кадров должно следовать свободным слотам, а не
   требовать физически невозможные 120/135/180 Гц.
6. Для подтверждённого barrier-only Vulkan приложения сравнить Buffer 0/1/2.
   Проверить в телеметрии buffered_owner=1: сохранённый выбор буфера сам по себе
   не означает активный независимый вывод. Для неподдержанного WSI фиксировать
   fallback, а не считать его успешным owner-тестом. Buffer 0 сейчас real-only,
   когда отсутствует причинно доступный слот интерполяции.
7. Менять refresh во время работы, кратко и длительно перегружать GPU, менять
   размер/полноэкранный режим, пересоздавать swapchain, выходить из игры. Проверить
   отсутствие зависаний, утечек GPU памяти, повторного ожидания binary semaphore
   и продолжения генерации после DEVICE_LOST.
8. Для каждой точки собрать p50/p95/p99 общего motion analysis, G1/G2/G3,
   reconstruction/upscale, accepted ratio и source FPS degradation относительно
   baseline. Указать количество образцов, прогрев и доверительные ограничения.
   Показать buffer occupancy/age, dropped/late/expired, реальные и synthetic
   WSI handoffs. Не складывать Source FPS и Generated FPS для объявления scanout.
9. Физический вывод измерять независимым capture/high-speed camera/надёжной
   display timing аппаратурой; проверить уникальность и порядок изображений,
   а не только счётчик WSI. Для задержки использовать одинаковый input-to-photon
   метод для baseline и Buffer 0/1/2. Не вычислять измеренную задержку из числа
   буферов. Сохранить кадры с движущимися контурами для визуального сравнения.
10. Экспортировать отчёт из Decky. Приложить версии SteamOS, Gamescope, Mesa/RADV,
    Proton/DXVK/VKD3D, игры и разрешение, ZIP checksum, source commit и настройки.
    При недостижении цели назвать измеренный предел: analysis, reconstruction,
    queue delay, WSI, power throttling или падение нативного FPS.

Критерий выпуска: все обязательные software gates и аппаратные точки выполнены,
WSI-контракт игры поддержан, стоимость x3/x4 растёт медленнее повторного analysis,
пользователь принимает измеренную задержку и падение source FPS. До этого PR
остаётся draft, стабильная версия не заменяется.
