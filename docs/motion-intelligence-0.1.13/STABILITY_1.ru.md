## Изменения

Обычный поддерживаемый WSI теперь может удерживать дополнительные реальные
изображения Buffer 1/2. Для этого нужны same-device FIFO, приватный
`VK_GOOGLE_display_timing` и запас изображений поверхности. Gamescope в
полученном отчёте предоставлял этот timing-контракт. После успешного refresh-query
готовые кадры передаются compositor заранее с неизменными временными метками.
Рабочий поток не спит до предыдущего B, поэтому может обработать следующую пару
до её временных слотов. Это отдельный совместимый WSI-путь; он не объявляется
полноценным Virtual Source WSI или независимым Output Owner.

При отсутствии приватного timing-контракта сохраняется обычный Buffer 0:
задерживать обычный worker на несколько периодов нельзя — это уменьшало
source throughput в проверке. Независимый Output Owner продолжает поддерживать
0/1/2 в пределах прежнего ограниченного opt-in контракта. При конечном лимите
изображений глубина уменьшается. Если создание расширенного пула не удалось,
есть повторная попытка без дополнительных изображений буфера, затем обычный
WSI fallback. Число запрошенных spare-изображений для ×4 исправлено на четыре.

В активном буфере GPU ring увеличен с двух до четырёх слотов. Ожидаемая
заполняемость в один/два кадра не считается перегрузкой; переполнение сверх этой
глубины уступает место реальным кадрам. Устаревшие задания и семафоры остаются
ограниченными жизненным циклом swapchain. Приложен тест: два удерживаемых кадра
не отменяют генерацию, третий включает давление до отправки GPU-команды.

После отказа по GPU-бюджету в буферизованном пути сохраняется дешёвое обновление
истории без synthetic. Следующий допустимый слот не тратится на обязательный
пустой прогрев истории. Непрерывное обновление истории также сохраняет HUD
счётчики. Реальная потеря истории, scene cut и ошибка ресурсов остаются поводами
для её сброса.

Общий refinement Balanced использует четыре выборки half-resolution RGB и один
ограниченный поиск по четырём соседям. Ultra Lite использует четыре выборки
кэшированной luma с таким же ограниченным уточнением. Quality сохраняет плотную
RGB-проверку и два масштаба поиска. Scene cut всё ещё проверяется по исходному
RGB, один раз на группу блоков: снижение разрешения не заменяет его сравнением
яркости. Общие flow/confidence повторно используются всеми тремя выходами.

Автоматическое снижение стоимости учитывает время GPU и достоверную задержку
начала исполнения. Качество может снижаться до Ultra Lite, затем восстанавливаться
после 240 дешёвых измерений. Выбранное качество служит верхним пределом;
отдельный Adaptive разрешает возврат до Quality. Множитель не меняется.

Decky показывает фактическую глубину рядом с выбранной, тип вывода, очередь,
возраст задания и действующее качество. `buffer_state` содержит все три GPU
бюджета и четыре временные цели. `synthetic_lifecycle` теперь содержит PID для
однозначного сопоставления потоков телеметрии. Старые поля `pair` сохранены для
совместимости анализаторов; полные G1/G2/G3 события находятся в lifecycle.

## Проверки и границы результата

Пороги качества и прежние WSI-пороги приёмки не ослаблялись. Полные наборы
Flow Lite 2.0 проходят для Balanced, Ultra Lite, Quality и batched Balanced:
197 проверок на набор, 0 ошибок. Проверены панорамы, статический UI, движущиеся
объекты, duplicate/cut recovery, временные коэффициенты и независимые три выхода.
Старый диагностический Flow Lite 1.0 сохраняет четыре известных отрицательных
проверки: coloured pan (13,55 dB) и три проверки cut/endpoint. Это те же ошибки,
что в исходном сравнении; они не объявляются успешными и пороги не меняются.

На software Vulkan проходят ×2/×3/×4, mutable-format WSI, ограниченные очереди,
инъекция отказов ring/TE, независимые Buffer 0/1/2 и packed10/FP16/PQ. Одна
packed10-комбинация без BLIT_DST явно пропускается. На Xvfb/lavapipe нет приватного
compositor timing: новая матрица проверяет безопасный Buffer 0 fallback, включая
приём трёх выходов. Передача будущих слотов без CPU sleep проверяется настоящим
production packet builder с записывающим WSI; это не аппаратный compositor-тест.
Валидация не сообщает ошибок; предупреждения GENERAL-layout о потенциальной
производительности сохраняются.

Санитизированная выборка из 256 уже отправленных аппаратных заданий проверяет
арифметику дополнительного времени буфера. Она смещена отбором успешных
диспетчеризаций и не предсказывает FPS или долю принятия всего прогона.

Сравнение GPU timestamp до/после на llvmpipe сохраняется в
`evidence/stability-software-performance.json`. Это небольшой программный
тест на 1280×800, не измерение RDNA2. Для Balanced p50 общего refinement снизился
с 48,140 до 14,696 мс, а GPU cost пары с одним synthetic — с 146,325 до
111,079 мс (примерно −24%). Ultra Lite показывает 91,705 мс на пару; это другой
профиль. Для двух/трёх synthetic Balanced измерены 138,855 / 268,658 мс на пару
и 64,255 / 74,495 МБ выделений против 54,015 МБ для одного выхода. Motion analysis
остаётся общим. Малые выборки и software renderer не подтверждают величину
ускорения на RDNA2. Нового аппаратного прогона этой сборки нет.
Стабильные 90 Гц, влияние на исходный FPS, реальная задержка и мощность после
изменений пока не установлены. Насыщенный GPU не получает дополнительную
вычислительную мощность от увеличения буфера.

## Следующий запуск на Deck

Установить ZIP Stability 1 поверх Launch fix 1, открыть GSF и выбрать игру.
Существующий профиль и команда запуска сохраняются. Для исходного случая начать
с Buffer 2 и Balanced; система может снизить стоимость до Ultra Lite без смены
множителя. Перезапустить игру. В живой диагностике ожидается фактическая глубина
2 и `buffered WSI · timed`, если поверхность предоставила нужные изображения.
Если фактическая глубина меньше, это ограничение контракта, а не работа Buffer 2.
Для проверки результата использовать протокол `DECK_PROTOCOL.ru.md`, включая
прогон без генерации, Source FPS, WSI ratio и физический вывод отдельными метриками.
