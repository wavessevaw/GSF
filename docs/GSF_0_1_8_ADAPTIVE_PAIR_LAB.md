# GSF 0.1.8: эксперимент перепланирования пары и восстановления потока

## Изолированный режим

Обычный путь 0.1.7 не изменён. Эксперимент включается отдельно через `GFG_NATIVE_ADAPTIVE_PAIRS=1`, в Decky выбирается в меню диагностики, действует только в 2× same-device `lmc-gpu`.

## Алгоритм

- Исходный `frame_clock_pair` определяет дисплейную сетку и доступность пары. До конца обработки сохраняется базовая копия часов, поэтому временное продление одного B не переписывает историю и не создаёт дрейф.
- Оценка времени начала GPU-работы плюс наблюдавшаяся стоимость LMC даёт предварительный G1/B слот. Для B разрешён максимум двух дополнительных периодов обновления дисплея. Если пары нет, генерация пропускается, исходный B идёт по обычному пути.
- После фактического сигнала TE готовности G1 в worker G1 и B повторно размещаются в дисплейной сетке при неизменном жёстком пределе B. Порядок Vulkan WSI-вызовов остаётся G1 перед B. Это не доказывает физический порядок scanout.
- `SYNCING → GENERATING → DEGRADED → REACQUIRE`. Серия отказов включает пропуск бесполезной работы, а ограниченный пробный режим через backoff 0,5–2 с не позволяет системе оставаться навсегда заблокированной устаревшим прогнозом.
- Отсутствие входного изображения на GPU до отправки TE по-прежнему нельзя измерить одними CPU Present timestamps. Новый режим экспериментальный, это не доказанная GPU-ready коррекция.

## Проверки

Чистая C-модель: 2200 непостоянных интервалов с повторными тяжёлыми окнами, принудительные тайм-ауты, чистый сценарий, потеря истории, backpressure, повторное восстановление, проверка ограниченного B. Native CI отдельно проверяет старую реализацию и наличие выключенного по умолчанию режима. Все существующие тесты TE, Game Mode, WSI, packed10 и device ownership должны пройти.

## Запреты

Нельзя обещать физический множитель 2× по успешным WSI или UI счётчикам. Нельзя повышать долгосрочную задержку настоящего кадра, расширять packed10 guard либо сливать эксперимент без квалификации на Gamescope/Steam Deck.
