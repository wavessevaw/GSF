**GSF 1.4.2 Kedavra**: steady speed at every multiplier, including fractional ones like ×2.25, and no more jumps after a game stall.

Install: Decky → Settings → Developer → Install plugin from zip → `GSF-Kedavra-1.4.2.zip`, then **Setup → Reinstall Gamescope KEDAVRA** and reboot (the engine changed). The zip installs over 1.4.1 in place. Details: [README](https://github.com/wavessevaw/GSF/blob/v1.4.2/README.md).

### New in 1.4.2

Found in Deck reports on 1.4.1: about a third of all refreshes ran at a changed speed (0.6× or 1.25×). The scheduler kept the delay at the lowest value it had ever reached, so every slightly late game frame meant a slow-down followed by a speed-up. That is the judder at ×2.25 and in other modes.

- **Steady delay instead of constant catch-up.** A slow-down is no longer paid back with a speed-up. The picture keeps the extra refresh of delay and gives it back gently (1.125×) only after a calm second.
- **Fractional caps on their real rhythm.** At 90 Hz, base 40 (×2.25) releases the game on a 2-2-2-3 refresh pattern and base 35 (×2.6) on its own pattern. The scheduler now expects each frame where the pattern puts it, not at the mean, so a 2-refresh gap is not taken for an early frame and a 3-refresh gap for a late one.
- **No jump after a stall.** After a game stall at ×2, the long interval was filled with only one intermediate and then the picture jumped ahead. Intervals up to 2×multiplier+4 refreshes are now filled one refresh at a time.

Scheduler simulation, 1.4.1 → 1.4.2 (3 seeds × 180 seconds per case, with occasional 50 ms game spikes, the limiter modelled with its real fractional pattern). "Speed changes" is the share of refreshes where the picture moves at a visibly different speed.

| Case | Hitches per minute | Speed changes | Median latency |
|---|---|---|---|
| ×2 at 90 Hz (base 45), game near its cap | 39.9 → 8.8 | 18.3 → 0.6 % | 37.8 → 40.1 ms |
| ×2.25 at 90 Hz (base 40), near cap | 9.2 → 8.4 | 3.2 → 0.6 % | 42.9 → 43.4 ms |
| ×2.25 at 90 Hz (base 40), game with room | 9.3 → 6.4 | 6.9 → 0.7 % | 38.8 → 48.2 ms |
| ×2.6 at 90 Hz (base 35), near cap | 9.9 → 6.2 | 10.3 → 0.9 % | 40.6 → 51.4 ms |
| ×3 at 90 Hz (base 30), near cap | 9.2 → 5.7 | 16.7 → 0.4 % | 46.3 → 51.2 ms |
| ×3.75 at 90 Hz (base 24), near cap | 6.7 → 4.5 | 19.8 → 0.5 % | 52.4 → 62.9 ms |
| ×2 at 60 Hz (base 30), near cap | 3.4 → 2.4 | 11.8 → 0.3 % | 55.4 → 57.4 ms |
| ×2.4 at 60 Hz (base 25), near cap | 2.4 → 1.0 | 2.5 → 0.4 % | 63.2 → 76.0 ms |
| ×3 at 60 Hz (base 20), near cap | 1.9 → 1.2 | 20.1 → 0.2 % | 68.5 → 75.1 ms |

Jumps of more than 1.75 frames at ×2, base 45: about 9 per minute → 0.

The price: with a game near its cap or a fractional base, the median delay is up to one refresh longer (about 11 ms at 90 Hz, up to 13 ms at 60 Hz), because the picture no longer runs on the very edge of the newest frame. No GPU change.

### Status

Experimental. **All numbers above come from the scheduler simulator, not from a Steam Deck.** To check on a Deck:
1. Play the same game in the same mode as on 1.4.1, ×2.25 especially.
2. Record a trace in **Pace** and press **Save report to Desktop**.
3. Compare `hitches_per_min`, the catch-up share and latency with 1.4.1.

**GSF 1.4.2 Kedavra**: ровная скорость на всех множителях, включая дробные вроде ×2.25, и больше никаких скачков после подвисаний игры.

Установка: Decky → Настройки → Разработчик → Установить плагин из zip → `GSF-Kedavra-1.4.2.zip`, затем **Setup → Reinstall Gamescope KEDAVRA** и перезагрузка (движок изменился). Zip ставится поверх 1.4.1. Подробно: [README](https://github.com/wavessevaw/GSF/blob/v1.4.2/README.ru.md).

### Новое в 1.4.2

Найдено в отчётах с Deck на 1.4.1: примерно треть всех обновлений экрана шла с изменённой скоростью (0,6× или 1,25×). Планировщик держал задержку на самом низком значении, которого когда-либо достиг, поэтому каждый чуть опоздавший кадр игры давал замедление, а за ним ускорение. Это и есть рывки на ×2.25 и в других режимах.

- **Устойчивая задержка вместо постоянного догона.** Замедление больше не отыгрывается ускорением. Картинка оставляет себе лишнее обновление задержки и плавно (1,125×) отдаёт его только после спокойной секунды.
- **Дробная база в её настоящем ритме.** При 90 Гц база 40 (×2.25) выпускает игру по ритму 2-2-2-3 обновления, база 35 (×2.6) по своему. Планировщик теперь ждёт каждый кадр там, где его ставит ритм, а не по среднему, и не принимает промежуток в 2 обновления за ранний кадр, а в 3 за поздний.
- **Нет скачка после подвисания.** После подвисания игры на ×2 длинный промежуток заполнялся всего одним промежуточным кадром, а потом картинка прыгала вперёд. Теперь промежутки до 2×множитель+4 обновлений заполняются по одному кадру на обновление.

Симуляция планировщика, 1.4.1 → 1.4.2 (3 сида по 180 секунд, редкие всплески игры по 50 мс, лимитер с настоящим дробным ритмом). «Смены скорости» — доля обновлений, на которых картинка идёт с заметно другой скоростью.

| Случай | Рывков в минуту | Смены скорости | Медианная задержка |
|---|---|---|---|
| ×2 на 90 Гц (база 45), игра у лимита | 39,9 → 8,8 | 18,3 → 0,6 % | 37,8 → 40,1 мс |
| ×2.25 на 90 Гц (база 40), у лимита | 9,2 → 8,4 | 3,2 → 0,6 % | 42,9 → 43,4 мс |
| ×2.25 на 90 Гц (база 40), с запасом | 9,3 → 6,4 | 6,9 → 0,7 % | 38,8 → 48,2 мс |
| ×2.6 на 90 Гц (база 35), у лимита | 9,9 → 6,2 | 10,3 → 0,9 % | 40,6 → 51,4 мс |
| ×3 на 90 Гц (база 30), у лимита | 9,2 → 5,7 | 16,7 → 0,4 % | 46,3 → 51,2 мс |
| ×3.75 на 90 Гц (база 24), у лимита | 6,7 → 4,5 | 19,8 → 0,5 % | 52,4 → 62,9 мс |
| ×2 на 60 Гц (база 30), у лимита | 3,4 → 2,4 | 11,8 → 0,3 % | 55,4 → 57,4 мс |
| ×2.4 на 60 Гц (база 25), у лимита | 2,4 → 1,0 | 2,5 → 0,4 % | 63,2 → 76,0 мс |
| ×3 на 60 Гц (база 20), у лимита | 1,9 → 1,2 | 20,1 → 0,2 % | 68,5 → 75,1 мс |

Скачков больше чем на 1,75 кадра на ×2, база 45: около 9 в минуту → 0.

Цена: когда игра у самого лимита или база дробная, медианная задержка до одного обновления больше (около 11 мс при 90 Гц, до 13 мс при 60 Гц), потому что картинка больше не идёт по самому краю новейшего кадра. Нагрузка на GPU не изменилась.

### Статус

Экспериментально. **Все цифры выше получены в симуляторе планировщика, а не на Steam Deck.** Как проверить на Deck:
1. Сыграйте в ту же игру в том же режиме, что на 1.4.1, особенно ×2.25.
2. Запишите трассу в **Pace** и нажмите **Save report to Desktop**.
3. Сравните `hitches_per_min`, долю догона и задержку с 1.4.1.
