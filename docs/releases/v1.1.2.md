**GSF 1.1.2 Kedavra**: x2 / x3 frame generation for Steam Deck in Gaming Mode, inside a patched Gamescope, controlled from Decky. No Lossless Scaling. No launch command.

Install: Decky → Settings → Developer → Install plugin from zip → `GSF-Kedavra-1.1.2.zip`, then **Setup → Reinstall Gamescope KEDAVRA** and reboot. The zip installs over 1.1.1 in place. Details: [README](https://github.com/wavessevaw/GSF/blob/v1.1.2/README.md).

### New in 1.1.2

- **Cheaper motion analysis.** Each block's own window is read once per search instead of once per candidate, which halves the texture reads of the search. On lavapipe the analysis of a frame pair goes from about 154 to 85–91 ms (old and new run alternately). The generated images are unchanged in every test scene. Less GPU time per pair should mean fewer repeats from late analysis (`me_late`), but that is not measured on the Deck yet.
- **Cheaper vector selection.** Identical candidates are matched once, and the sub-pixel fit reuses the best candidate's error: 10–15% less on lavapipe, same images (within 0.01 dB).
- **Stopping a Pace recording.** It has restarted Gaming Mode on the Deck. The trace file is now opened, written and closed on its own thread, so stopping a trace does no file work in the compositor, and the plugin analyses the trace only after Gamescope has closed it. The cause of the restart is not confirmed, so this may not be the fix.
- **Crash records in the report.** **Save report to Desktop** now includes `coredumpctl` (the stack of a crashed Gamescope or Steam) and the kernel GPU log, so a crash can be told apart from a GPU reset. If Gaming Mode restarts, save a report right after and send it.

### Status

Experimental. The speed-ups are measured on lavapipe (software Vulkan). **They have not been measured on a Steam Deck.** Run **Setup → GPU benchmark** and record a trace in **Pace**, then send them with **Save report to Desktop**.

**GSF 1.1.2 Kedavra**: генерация кадров x2 / x3 для Steam Deck в игровом режиме внутри пропатченного Gamescope, управление из Decky. Без Lossless Scaling. Без команд запуска.

Установка: Decky → Настройки → Разработчик → Установить плагин из zip → `GSF-Kedavra-1.1.2.zip`, затем **Setup → Reinstall Gamescope KEDAVRA** и перезагрузка. Zip ставится поверх 1.1.1. Подробно: [README](https://github.com/wavessevaw/GSF/blob/v1.1.2/README.ru.md).

### Что нового в 1.1.2

- **Анализ движения дешевле.** Окно самого блока читается один раз на поиск, а не для каждого кандидата, так что выборок из текстур при поиске вдвое меньше. На lavapipe анализ пары кадров занимает 85–91 мс вместо примерно 154 (старая и новая версии запускались попеременно). Сгенерированные кадры во всех тестовых сценах не изменились. Меньше времени GPU на пару должно означать меньше повторов из-за опоздавшего анализа (`me_late`), но на Deck это ещё не измерено.
- **Выбор вектора дешевле.** Одинаковые кандидаты сравниваются один раз, а субпиксельное уточнение берёт уже посчитанную ошибку лучшего кандидата: на lavapipe это на 10–15% меньше работы, картинка та же (в пределах 0,01 дБ).
- **Остановка записи в Pace.** Раньше она перезапускала игровой режим на Deck. Теперь файл трассы открывается, пишется и закрывается в отдельном потоке, и композитор при остановке с файлом не работает. Плагин разбирает трассу только после того, как Gamescope её закрыл. Причина перезапуска не подтверждена, так что это может быть ещё не исправление.
- **Записи о падениях в отчёте.** **Save report to Desktop** теперь добавляет `coredumpctl` (стек упавшего Gamescope или Steam) и журнал GPU из ядра, чтобы падение можно было отличить от сброса GPU. Если игровой режим перезапустится, сразу сохраните отчёт и пришлите его.

### Статус

Экспериментально. Ускорение измерено на lavapipe (программный Vulkan). **На Steam Deck оно не измерено.** Запустите **Setup → GPU benchmark** и запишите трассу в **Pace**, затем пришлите всё через **Save report to Desktop**.
