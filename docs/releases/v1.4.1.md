**GSF 1.4.1 Kedavra**: smoother pacing and steadier screen edges, with the same latency and no extra GPU work.

Install: Decky → Settings → Developer → Install plugin from zip → `GSF-Kedavra-1.4.1.zip`, then **Setup → Reinstall Gamescope KEDAVRA** and reboot (the engine changed). The zip installs over 1.4.0 or 1.4.1-rc.1 in place. Details: [README](https://github.com/wavessevaw/GSF/blob/v1.4.1/README.md).

### New in 1.4.1

This is 1.4.1-rc.1 as a stable release. The engine is the same as in rc.1.

- **Quarter speed instead of a freeze.** When the frames that will be ready would still run out, the picture briefly moves at a quarter of its speed instead of stopping. If the analysis of a pair finishes later than predicted, the scheduler uses a half-step that is really ready. Long game stalls still cannot be hidden.
- **Cheaper forecast.** The scheduler scans its history once per forecast, not once per forecast refresh.
- **Screen edges.** Near the edges the warp fades smoothly to the source frame that has the pixels, and the motion search no longer takes stretched edge pixels for a match.
- **Fewer reads.** Repeated colour reads of motion candidates are skipped, and slow or still pixels skip the blur square root. The analysis resolution and the sharp filter are unchanged. No new GPU pass, image or history frame.

Scheduler simulation (3 seeds × 180 seconds per case, with occasional game spikes):

| Case | Hitches per minute, 1.4.0 → 1.4.1 | Median latency |
|---|---|---|
| ×2 at 60 Hz, game near its cap | 5.28 → 0.45 | 54.57 → 54.56 ms |
| ×3 at 90 Hz, game near its cap | 11.58 → 7.08 | 45.06 → 45.06 ms |
| ×2 at 90 Hz, game near its cap | 16.07 → 9.10 | 37.36 → 37.36 ms |
| Base 24 at 90 Hz | 16.86 → 12.03 | 51.02 → 51.01 ms |
| ×3 at 90 Hz, game with room | 10.34 → 5.84 | 46.74 → 46.73 ms |

Image at 1280×800 (lavapipe): edges in a pan +0.75 dB, in a fast pan +0.22 dB; the camera sequence's frame-to-frame error is about 1.7 % lower (worst frame 23.2 → 23.4 dB), at base 24 too. Still frames and the objects/HUD scene are unchanged. Small losses remain, the largest 0.12 dB at the edges of the dolly scene at base 24. Full results: [`docs/kedavra/evidence/1.4.1-rc.1`](https://github.com/wavessevaw/GSF/tree/v1.4.1/docs/kedavra/evidence/1.4.1-rc.1).

### Status

Experimental. **The numbers above come from the scheduler simulator and lavapipe, not from a Steam Deck.** A lower GPU cost on real hardware is not confirmed. To check on a Deck:
1. Play the same game in the same mode as on 1.4.0.
2. Record a trace in **Pace** and press **Save report to Desktop**.
3. Compare `hitches_per_min`, `gpu_us_avg` and `gpu_analysis_us_avg` with 1.4.0.

**GSF 1.4.1 Kedavra**: более плавная подача кадров и устойчивые края экрана при той же задержке и без лишней работы GPU.

Установка: Decky → Настройки → Разработчик → Установить плагин из zip → `GSF-Kedavra-1.4.1.zip`, затем **Setup → Reinstall Gamescope KEDAVRA** и перезагрузка (движок изменился). Zip ставится поверх 1.4.0 или 1.4.1-rc.1. Подробно: [README](https://github.com/wavessevaw/GSF/blob/v1.4.1/README.ru.md).

### Новое в 1.4.1

Это 1.4.1-rc.1 в виде стабильного выпуска. Движок тот же, что в rc.1.

- **Четверть скорости вместо остановки.** Если готовые кадры всё равно кончаются, картинка ненадолго идёт в четверть скорости, а не замирает. Если анализ пары закончился позже ожидаемого, планировщик берёт полушаг, который действительно готов. Долгие подвисания игры по-прежнему не скрыть.
- **Дешевле прогноз.** Планировщик проходит по истории один раз на прогноз, а не на каждое обновление прогноза.
- **Края экрана.** У краёв warp плавно переходит на тот исходный кадр, где пиксели есть, а поиск движения больше не принимает растянутые крайние пиксели за совпадение.
- **Меньше чтений.** Повторные чтения цвета кандидатов пропускаются, а медленные и неподвижные пиксели обходятся без корня в размытии. Разрешение анализа и резкий фильтр не изменились. Новых проходов GPU, изображений и кадров истории нет.

Симуляция планировщика (3 сида по 180 секунд на случай, с редкими всплесками у игры):

| Случай | Рывков в минуту, 1.4.0 → 1.4.1 | Медианная задержка |
|---|---|---|
| ×2 на 60 Гц, игра у самого лимита | 5,28 → 0,45 | 54,57 → 54,56 мс |
| ×3 на 90 Гц, игра у самого лимита | 11,58 → 7,08 | 45,06 → 45,06 мс |
| ×2 на 90 Гц, игра у самого лимита | 16,07 → 9,10 | 37,36 → 37,36 мс |
| База 24 на 90 Гц | 16,86 → 12,03 | 51,02 → 51,01 мс |
| ×3 на 90 Гц, игра с запасом | 10,34 → 5,84 | 46,74 → 46,73 мс |

Картинка в 1280×800 (lavapipe): края при панораме +0,75 дБ, при быстрой панораме +0,22 дБ; ошибка между кадрами в последовательности камеры примерно на 1,7 % меньше (худший кадр 23,2 → 23,4 дБ), на базе 24 тоже. Неподвижные кадры и сцена objects/HUD не изменились. Есть небольшие потери, самая большая 0,12 дБ на краях сцены dolly на базе 24. Полные результаты: [`docs/kedavra/evidence/1.4.1-rc.1`](https://github.com/wavessevaw/GSF/tree/v1.4.1/docs/kedavra/evidence/1.4.1-rc.1).

### Статус

Экспериментально. **Цифры выше получены в симуляторе планировщика и на lavapipe, а не на Steam Deck.** Меньшая нагрузка на реальном GPU не подтверждена. Как проверить на Deck:
1. Сыграйте в ту же игру в том же режиме, что на 1.4.0.
2. Запишите трассу в **Pace** и нажмите **Save report to Desktop**.
3. Сравните `hitches_per_min`, `gpu_us_avg` и `gpu_analysis_us_avg` с 1.4.0.
