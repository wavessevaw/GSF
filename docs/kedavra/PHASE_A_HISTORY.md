# KEDAVRA — Фаза A. Расследование истории GSF

**Дата:** 2026-10-21. **Основа:** `main` = `e14f169`, 60 удалённых веток, PR #7–#61
репозитория `wavessevaw/GSF`, документы `docs/fg3/`, `docs/archive/`, `docs/research/`,
отчёты с устройства, процитированные в `docs/GSF_*`. История до 2026-10-18 доступна только
в GFG-Extreme (см. `MIGRATION.md`); здесь она восстановлена по перенесённым документам.

**Статус оценок:** всё ниже — анализ документов и кода. Новых измерений на Steam Deck
в этой фазе нет и быть не может (в контейнере нет устройства).

## 2. Ключевые факты с устройства (дословно из отчётов)

* `docs/GSF_0_1_7_HARDWARE_RESULT_20261019.md`: медиана **submit → начало GPU 41.258 мс**,
  span LMC 8.0 мс, **0 принятых синтетических кадров после первых 60 с**, источник ~42–43 кадра/с,
  глобальная загрузка GPU **медиана 99%**. CPU-фазы (0.05–0.36 мс) задержку не объясняют.
* `docs/GSF_CALIBRATED_ADMISSION_0_1_7.md`: после 60 с все 826 выходов готовы после дедлайна,
  824 начали выполняться на GPU уже после дедлайна.
* `docs/GSF_AC_ORIGINS_PACING_20261018.md`: 2474 диспетчеризации → 162 принятых G1;
  159 из них в первые 20 с.
* PR #57 (Alpha 4 трасса): при задержке воспроизведения ~2 тика успели бы только
  346/7497 (4.6%) и 20/2655 (0.8%) слотов.
* `docs/GSF_GAME_MODE_TIMING_FEEDBACK.md`: тестовое приложение в Game Mode давало интервалы
  ~11.1 мс на 45→90, но 45→90 случаи теряли X11-окно (`VK_ERROR_OUT_OF_DATE_KHR`),
  а низкие частоты падали по stack protector в `GetPastPresentationTimingGOOGLE` Gamescope 3.16.16.

Ни в одном отчёте нет измерения, сильнее «WSI принял present». Нет ни одной трассы
KMS page flip с идентификатором кадра и ни одной оптической записи.

## 3. Классификация отказов FG-01…FG-12

Формат: **доказательство → корневая причина → последствия → исправление → проверка от повторения.**

### FG-12. Фундаментальное архитектурное ограничение (главное)
* **Доказательство.** Все поколения 1–5 исполняют генерацию внутри процесса игры
  (Vulkan-слой) и показывают через swapchain игры. Задержка 35–41 мс до старта GPU
  при 99% загрузке и неподвижном CPU-пути; в Alpha 5 при отдельной compute-очереди
  успевают <5% слотов.
* **Причина.** Слой в игре (а) делит GPU с игрой без приоритета: процесс игры не имеет
  `CAP_SYS_NICE`, поэтому `VK_QUEUE_GLOBAL_PRIORITY_HIGH/REALTIME` ему недоступен, и работа
  FG стоит в очереди аппаратного планировщика за кадрами игры; (б) показывает кадры
  через Gamescope FIFO, где композитор принимает не более одного коммита окна за vblank
  и применяет к окну лимитер FPS (`steamcompmgr.cpp: window_refresh_cycle`, `hold_done_commit`);
  (в) не знает реального времени vblank и опирается на `clock_nanosleep` + предсказания.
* **Последствия.** Синтетический кадр стабильно опаздывает; каждая «починка» сводилась
  к отбрасыванию опоздавших кадров (0.1.3, 0.1.7, #57), т.е. к выключению генерации.
* **Исправление.** Перенести генерацию и выбор кадра на каждый vblank в Gamescope:
  он уже владеет compute-очередью с `VK_QUEUE_GLOBAL_PRIORITY_REALTIME_EXT`
  (`rendervulkan.cpp`, ~545), таймером vblank и временем реального page flip от ядра
  (`DRMBackend.cpp page_flip_handler`). См. Фазу B.
* **Проверка.** Трасса каждого flip: время ядра + (id исходного кадра, фаза k/N).
  Критерий: ≥99.5% vblank несут новый кадр в правильном порядке.

### FG-01. Захват исходного кадра
* **Доказательство.** `unsupported-swapchain-flags` для DXVK MUTABLE_FORMAT (AC Origins, 0 генерации);
  internal.4: MAILBOX + A2B10G10R10 → мост не стартовал; `VK_SWAPCHAIN_CREATE_PRESENT_TIMING_BIT_EXT`
  и NULL `pTimingInfos` отклоняются (`GSF_GAMESCOPE_PRESENT_TIMING_20261018.md`).
* **Причина.** Перехват на уровне Vulkan API обязан понимать каждый флаг/pNext/формат
  каждого рендерера (DXVK, VKD3D, нативный Vulkan, OpenGL через Zink не покрыт вообще).
* **Исправление.** В Gamescope источник — уже готовый dmabuf коммита окна, независимо
  от API игры; формат известен композитору.
* **Проверка.** Матрица: DXVK, VKD3D-Proton, нативный Vulkan, OpenGL; отказ = явный статус, не тихий 0.

### FG-02. Дефекты алгоритма интерполяции
* **Доказательство.** Дешёвые блоки раздваивают малые объекты (−2.207 dB, bolt);
  не пойманная склейка сцены (`ARCHITECTURE_DECISION_1_0.md`); Flow Lite признан хуже на краях.
  Качество в реальной игре на устройстве ни разу не измерено.
* **Причина.** Алгоритмы выбирались по lavapipe, без бюджета Deck; дорогие (LMC IRLS/RANSAC)
  не помещались в бюджет, дешёвые — без контроля качества.
* **Исправление.** Двухуровневая схема: оценка движения один раз на пару на 1/4 разрешения
  + дешёвая деформация на каждый vblank; детектор склейки и откат к реальному кадру.
* **Проверка.** Синтетические последовательности с эталоном промежуточного кадра:
  PSNR(интерполяция) должен значимо превышать PSNR(смешивание) и PSNR(дубль).

### FG-03. Чрезмерная задержка вычисления промежуточного кадра
* **Доказательство.** Span LMC 7–9 мс + 35–41 мс ожидания старта ≫ окно ~8 мс.
* **Причина.** Не время шейдера, а очередь (FG-12) плюс выполнение всей работы пары
  только после прихода B в узком окне.
* **Исправление.** Приоритетная очередь композитора; оценка движения сразу по готовности B,
  а деформация — отдельный маленький шаг перед каждым vblank; явный бюджет и измерение
  временными метками GPU.
* **Проверка.** p99(ME) + p99(warp) < запас до vblank; при превышении — деградация (FG-11).

### FG-04. Неверный порядок кадров
* **Доказательство.** #45: фаза x3 1/2 вместо 2/3 в 4433 слотах; перенос B раньше G после давления (#45);
  «пачка» G1/G2/G3+B при позднем GPU (#53).
* **Причина.** Время показа выбирали в момент отправки работы и меняли задним числом;
  порядок не был инвариантом одной функции.
* **Исправление.** Фаза выбирается только в момент vblank функцией монотонного времени
  τ(T)=T−D; кадр, не готовый к своему vblank, не показывается позже.
* **Проверка.** Детерминированный тест: τ показанных кадров строго возрастает при любых
  джиттере, нагрузке, смене множителя.

### FG-05. Интеграция с Gamescope
* **Доказательство.** Порядок слоёв (PR #22), MAILBOX у драйверной стороны FROG WSI,
  stack corruption в `GetPastPresentationTimingGOOGLE` (3.16.16), потеря окна 45→90,
  лимитер Gamescope режет синтетические кадры вместе с игрой.
* **Причина.** Слой находился между игрой и Gamescope и боролся с его протоколом.
* **Исправление.** Генератор становится частью Gamescope; лимитер Steam ограничивает
  только игру, что и требуется (источник 30/45 кадров синхронно с vblank).
* **Проверка.** Тест на устройстве: лимитер 30 → 90 Гц выход, лог flip.

### FG-06. Нарушения VSync и тайминга дисплея
* **Доказательство.** Планирование по `CLOCK_MONOTONIC` + `desiredPresentTime`; `physical_displayed:null`
  во всех отчётах; `pixel_out` Gamescope — предсказание (`GSF_GAMESCOPE_PRESENT_TIMING_20261018.md`).
* **Причина.** Слой не знает фактических vblank.
* **Исправление.** Решение «что показать» принимается в цикле Gamescope, разбуженном его
  таймером vblank; фактическое время берётся из события page flip ядра.
* **Проверка.** P95 |интервал − 1/f| ≤ 1 мс по временам flip ядра.

### FG-07. Нестабильный frametime и неравномерная подача
* **Доказательство.** Хвосты до 69.8 мс после цели G (#45 локальный прогон); #60: разрывы >45 мс
  на 22.5→90; ранний B при давлении источника.
* **Причина.** FG-03 + FG-06 + политика «сначала реальный кадр» внутри потока present игры.
* **Исправление.** Выход каждый vblank; при неготовности повторяется последний кадр
  (учитывается как пропуск); задержка D адаптируется медленно и ограничена.
* **Проверка.** Метрики симулятора и анализатора трассы: доля пропусков, отсутствие
  колебаний короткий/длинный.

### FG-08. Переполнение очереди и нарушение владения буферами
* **Доказательство.** internal.4: 2986 потерь на кольце, 4183 на acquire; WRITE_AFTER_PRESENT
  в валидации; лимит «≤8 образов swapchain» ломает игры (AFMF FAQ); #59 очередь 1–8 кадров.
* **Причина.** Дополнительные образы приходилось брать у swapchain игры.
* **Исправление.** Выходные образы — собственные образы Gamescope; от игры удерживаются
  только два последних коммита (A, B) — те же буферы, что Gamescope уже держит.
* **Проверка.** Без изменения числа образов swapchain игры; счётчик удерживаемых буферов ≤ 2+1.

### FG-09. Жизненный цикл ресурсов Vulkan
* **Доказательство.** Ре-сигнал семафоров, `oldSwapchain`, recreate, `vkQueueWaitIdle` дренаж,
  VUID 03268 (relay mode), WAW в предикторе (internal.10).
* **Причина.** Чужие объекты (семафоры, образы, ID игры) при перехвате.
* **Исправление.** Только свои объекты Gamescope; dmabuf источника импортируется Gamescope
  как обычно; интерполятор создаёт свои образы на устройстве Gamescope.
* **Проверка.** Validation layers в тестах движка; смена размера/формата/окна сбрасывает историю.

### FG-10. Неверные измерения
* **Доказательство.** «WSI accepted» и счётчики выдавались за прогресс; глобальные медианы
  смешивали меню и игру (0.1.7, 1.587 мс); нет базового прогона без слоя; MangoHud/Steam FPS.
* **Причина.** Не было источника правды о показанных кадрах.
* **Исправление.** Трасса на каждый flip: `kms_ns`, `src_id`, `phase_num/den`, `kind`,
  `gpu_ready_ns`; плюс опциональная оптическая метка на экране для камеры.
* **Проверка.** Анализатор трассы считает метрики ТЗ только из времён ядра.

### FG-11. Чрезмерная нагрузка CPU/GPU
* **Доказательство.** GPU 99% при игре без ограничения FPS; LMC 7–9 мс на выход;
  ECO45/Flow Lite созданы именно ради 10–15 Вт.
* **Причина.** Тесты запускали игру без лимитера, т.е. без запаса GPU, который FG обязан
  иметь по определению; дорогой анализ на каждый выход.
* **Исправление.** FG требует лимит источника (лимитер Steam 30/45); анализ один раз на пару
  на 1/4 разрешения; деформация на выход дешёвая; явная деградация (меньше уровней,
  пропуск интерполяции → только реальные кадры) с телеметрией.
* **Проверка.** GPU-метки ME/warp, FPS игры с FG и без (A/B/A), мощность APU.

## 4. Что переиспользуется

1. Требования и методика доказательства из `fg3/HARDWARE_ACCEPTANCE_1_1.md`,
   `GSF_GAMESCOPE_PRESENT_TIMING_20261018.md` (уровни доказательности: WSI → композитор → KMS → оптика).
2. Набор синтетических сцен и метрик качества `engine/gfg-temporal/bench` — как идея
   эталонной проверки; новый тест использует собственные генераторы движения.
3. Знание о Gamescope: FROG WSI, лимитер, протокол таймингов, ошибки 3.16.16.
4. Вывод AFMF/FidelityFX: оценка движения по блокам на пирамиде яркости + деформация
   с проверкой согласованности достаточна по цене для 2×; для 3× анализ общий.
5. Отрицательный результат: перехват в процессе игры на устройстве не даёт стабильных
   промежуточных кадров — **не повторять под новым именем** (VIOLATION 11).

## 5. Отброшенные неподтверждённые допущения

* «41 мс — время шейдера» — нет: span 8 мс, остальное ожидание до старта.
* «Счётчик WSI = показанные кадры» — нет.
* «FG можно включать без лимита источника» — нет: при 99% GPU места для FG нет.
* «40→80 при 90 Гц» — физически невозможно равномерно: 80 не делит 90. Требуется 80 Гц панели.
* «Отбросить опоздавшие кадры = починить pacing» — это выключение генерации.
