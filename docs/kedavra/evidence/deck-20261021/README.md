# Steam Deck OLED, 2026-10-21: первый прогон (измерено)

Система: SteamOS 3.8.28 (20260922.1), RADV VANGOGH, Mesa 26.0.0-devel. Gamescope KEDAVRA
`aa289ea+` запущен из плагина 0.2.x, CAP_SYS_NICE есть, статус движка свежий.

## Бенчмарк движка (`bench.json`, RADV, 1280×800)

* корректность: 0 ошибок во всех сценариях;
* анализ пары кадров: 4,77 мс (медианы проходов); два промежуточных кадра: 0,99 мс
  (около 0,5 мс на кадр).

## Трасса KMS flip x2, 90 Гц, ~70 с (`trace-x2-run1.csv`, отчёт `.report.json`)

Измерено по меткам KMS page flip. **Требования не выполнены:**

* P95 ошибки интервала 44,5 мс, P99 44,5 мс (цель ≤1 / ≤2 мс);
* пропуски 2,9% (цель <0,5%); 1698 вблэнков без флипа на ~4700;
* шаги контента нерегулярны в 58% интервалов.

Наблюдения пользователя: мерцание и резко завышенный контраст при включении генерации.

## Причины, найденные по коду и трассе

1. **Цвет.** В Gamescope `setTextureSrgb(true)` привязывает UNORM-вид (сырые значения), а
   `false` привязывает `_SRGB`-вид, который декодирует в линейное. Копия кадра в кольцо
   шла с `false`. Кольцо хранило линейные значения, композитор декодировал их второй раз:
   темно и контрастно. Сквозные кадры при этом были нормальными, отсюда мерцание.
2. **Пропуски флипов.** Анализ (~4,8 мс GPU) записывался в тот же буфер команд, что и
   композиция кадра. Композиция не успевала к вблэнку, флип уезжал на следующий, и
   следующий кадр тоже терялся.

Исправления в коммите после этой трассы: сырые значения во всех проходах; анализ
отправляется отдельно после композиции, пара кадров доступна со следующего вблэнка;
HDR-слои идут без генерации. Повторное измерение на Deck ещё не проведено.
