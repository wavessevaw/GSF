# Kedavra: оптимизация без дополнительных проходов

Продолжение аудита 2026-10-22. Основа: engine c264c28 из GFG 3.0.0, main повторно проверен fetch. Изменения находятся в отдельной review-ветке; релиз не создаётся.

## Исправлено: чтение неинициализированного соседа

В `kfg_select.comp::repair` массив `nb` заполнялся по одному элементу, а spread сразу вычислялся относительно `nb[4]`. На i=0..3 центр ещё не загружен. Это неопределённое значение в GLSL, а не обязательно ноль. Оно влияло на ранний выход, то есть на применение repair и его стоимость. Компилятор/RADV может вести себя иначе, чем llvmpipe.

Теперь сначала загружаются все девять соседей, затем вычисляется spread. Девять texture fetch остаются девятью; нового dispatch/буфера нет. Это не обещание неизменного GPU time: исправленный early exit может запускать другую ветвь. Это устранение ошибки, а не визуальный фильтр.

## Уменьшена арифметика пороговых проверок

В warp три `length` нужны только для сравнения максимума с 2.0. Они заменены dot(v,v) и порогом 4.0. В repair аналогично порог 1.0. Число текстурных операций не увеличивается. Для конечных значений это эквивалентная геометрическая проверка; FP rounding вблизи границы требует A/B, поэтому не заявляем универсальную побитовую идентичность.

SPIR-V до/после: warp содержит 4→1 статических Length, selection 8→7. ImageFetch и ImageSampleExplicitLod counts не изменились. Это статический код, не число исполненных fetch и не RADV ISA. На 1280×800 warp удаляет три вычисления длины на каждый pixel, дошедший до проверки; scene-cut early exit туда не доходит. Реальный выигрыш зависит от ISA, occupancy и memory bottleneck.

## Проверка гипотезы confidence

`best_cost` смешивает data residual, consistency и prior; repair сравнивает его с raw cost другого вектора. Эксперимент `KFG_EXPERIMENT_RAW_CONFIDENCE` сохраняет `best_raw` вместо `best_cost` в .w без дополнительных cost() и выборок. Это минимальный A/B, а не законченная новая confidence model: residual относится ещё к положению до subpixel refinement, а выбор weight B остаётся прежним.

Если качество регрессирует, нельзя компенсировать его дополнительными repair rounds под видом «бесплатного» улучшения. Стандартный вариант не включает этот define. Полные результаты эксперимента перечислены ниже, в том числе отрицательные.

## Следующие пути: конкретные места и условия принятия

### 1. Повторное использование SAD при одинаковых predictors в ME

`kfg_me.comp::search` в non-coarsest ветви оценивает до шести predictors. У одинаковых векторов SAD одинаков, но prior последнего global predictor отличается. Кэшировать нужно только data term, не полную стоимость:

```glsl
float residual[6];
for (int i = 0; i < npred; ++i) {
    int same = -1;
    for (int j = 0; j < i; ++j)
        if (same < 0 && all(equal(preds[i], preds[j]))) same = j;
    residual[i] = same >= 0 ? residual[same] : sad(sa, sb, q, preds[i], size);
    vec2 origin = i == npred - 1 ? preds[i] : base;
    float score = residual[i] + u_lambda * 0.1 *
                  (abs(preds[i].x-origin.x) + abs(preds[i].y-origin.y));
    // Existing comparison/order/tie rule unchanged.
}
```

Один повтор экономит 9 filtered samples на finest или 25 на coarse уровне, но проверки и residual[6] могут увеличить registers/spills. Измерять частоту совпадений отдельно и проверять RADV occupancy; не включать автоматически по числу строк кода. Не распространять правило на approximate-equal vectors: тогда качество может меняться. Selection уже кэширует дубликаты, там повторно внедрять это не надо.

### 2. Не вычислять цвет стороны с нулевым вкладом

В warp после проверки out-of-frame `w_b` может быть точно 0 или 1; цвет отвергнутой стороны уже вычислен. Перенести определение inside/weight до ca/cb; при точном 0/1 не выполнять tap_sharp и blur taps этой стороны. В полностью fractional позиции это до пяти sharp taps и двух blur taps. Не округлять weight и не пропускать обе стороны вне изображения. Порядок scene cut/debug marker/scRGB сохранить.

Риск: wave divergence может съесть экономию; это нужно тестировать на частоте экранных границ и occlusions, а не только на static. Для HDR отдельно сравнить signed scRGB и PQ; NaN/Inf inputs не являются допустимой базой доказательства эквивалентности.

### 3. Visibility без двух exp: только отдельный измеряемый опыт

Математически нормализованные `wa=(1-t)*exp(-da/4)`, `wb=t*exp(-db/4)` можно выразить через один exp разности. Но текущий `max(wa+wb,1e-6)` меняет поведение при низкой суммарной confidence. Простая logistic substitution НЕ эквивалентна. Требуется либо сохранить текущий low-confidence fallback, либо обосновать новую модель; не включать такую замену как безусловную оптимизацию.

### 4. Уменьшать задержку через бюджет и bounded queue

Completion adapter и привязка flip cookie из ANALYSIS.ru.md приоритетнее агрессивного source cap. Поздняя генерация не должна вытеснять своевременный real frame. Не копить невыполнимые фазы; просроченную фазу пропускать с явным effective multiplier. Это исправляет политику очереди, но не устраняет необходимость дождаться B у interpolation. Измерять source acquire→flip, отдельно timestamp содержимого.

### 5. Проверить настоящий kernel pyramid перед настройкой motion search

`kfg_reduce.comp` называет фильтр tent с весами `[1,3,3,1]`, но четыре bilinear taps в `corner ± 1.0`, усреднённые с 0.25, дают равномерный separable 4×4 box: в каждой оси `[1,1,1,1]/4`. Это можно вывести из координат: две пары на −0.5 и 1.5 относительно 2p имеют веса 0.5/0.5 и не пересекаются. Поэтому рассуждения об alias suppression именно tent-фильтром сейчас ошибочны.

Для настоящего `[1,3,3,1]/8` достаточно заменить offsets ±1.0 на ±0.75: bilinear веса становятся 0.25/0.75 и 0.75/0.25, число taps прежнее. Но это **другой частотный отклик**, не автоматически лучшее качество. Проверять на fences/stairs и ошибке global motion до переноса; текущий box сильнее подавляет некоторые частоты. В этом патче исправлен только комментарий, sampling не изменён.

## Что не предлагается как бесплатное улучшение

Дополнительный bilateral pass, больше ME radius, дополнительный repair round, отдельная CNN, общая замена blur на sharpening. Все они требуют бюджета или создают новые артефакты. Предыдущий no-blur A/B уже показал ухудшение occlusion; этот результат остаётся действующим.

## Воспроизводимость

Для исправления + арифметики: обычная сборка shader и `make -C kedavra test-engine`. Для confidence: отдельно собрать только selection с `-DKFG_EXPERIMENT_RAW_CONFIDENCE=1`, остальные SPIR-V идентичны. Для изоляции init-fix использован исходный shader с разделением циклов, но прежними length. Файл этого контрольного shader сохранён рядом с результатами. Все варианты запускаются одним baseline kfg_vktest, 1280×800, llvmpipe. Сравнение — `docs/deep-review/compare_engine.py`. Полный повтор: `bash docs/deep-review/run_shader_variants.sh /path/to/preserved-c264c28-build /tmp/kfg-shader-review`; build должен содержать исходные SPIR-V и завершённый baseline engine.json, не пересобирать его текущими shader.

Ни стоимость кадра на Deck, ни ускорение RADV здесь не измерены. Условия принятия: отсутствие новых провалов обязательных quality/temporal/HDR gates; climb показывать отдельно; на устройстве p95 полного FG GPU cost и source→flip не хуже baseline при той же сцене/температуре/лимитах. Лабораторная метрика PSNR не заменяет эти условия.

## Результаты трёх прогонов

Все прогоны закончились exit 0, обязательные SDR/HDR gates не получили новых failures. Три ungated фазы climb по-прежнему неуспешны; temporal-секции stairs/slow_pan/slow_stairs/climb также informative, поэтому общий PASS не гарантирует отсутствие ухудшения.

| Вариант | Изменение PSNR по 33 фазам относительно baseline | Temporal stairs (меньше лучше) | Решение |
|---|---:|---:|---|
| baseline | — | 9.9617 | исходная точка, содержит undefined read |
| только repair init | −0.014…+0.006 dB | 9.9636 | исправить undefined read; улучшения метрик повсеместно нет |
| init + squared thresholds | −0.014…+0.006 dB | 9.9636 | оставить сокращение арифметики, подтвердить RADV time отдельно |
| плюс raw confidence | −0.612…+0.089 dB | 10.4710 | отклонить для default |

JSON init-only и squared полностью совпали, включая camera, temporal и HDR разделы. Это равенство записанных округлённых метрик на этой матрице, не доказательство побитового равенства изображений на всех устройствах. Небольшие изменения init-only показывают, что исправление порядка чтения действительно меняет поведение старого shader; нельзя приписывать их арифметической оптимизации.

Raw confidence также ухудшил camera mean PSNR 27.835→27.537 и camera HUD max 4.130→4.554. Нужна согласованная модель confidence/refinement/repair, простая подмена .w не принята. Define оставлен только для воспроизведения отрицательного опыта, по умолчанию выключен.

Полные JSON/логи и per-phase comparison лежат в `optimization-evidence/`; `baseline-sha256.txt` идентифицирует использованный binary и исходные shaders. Во время трёх запусков процессы работали одновременно, поэтому их wall-clock time принципиально не используется как performance benchmark.
