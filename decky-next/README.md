# GSF Next 0.2.0-alpha.5

Отдельный экспериментальный Decky-плагин на открытом AFMF-Linux / AMD FidelityFX
Optical Flow. Не использует старый движок Flow Lite и компоненты Lossless Scaling.
Не является DLSS/FSR SDK-интеграцией в игру: доступны только готовые цветовые кадры,
без настоящих motion vectors/depth. Steam Deck OLED ещё не квалифицирован.

1. Установите ZIP через Decky → Developer → Install plugin from ZIP.
2. Уберите прежнюю команду `gsf-test` и другие frame-generation wrappers из запуска игры.
3. Выберите игру в **GSF Next**, нажмите **Подготовить игру**.
4. Вставьте показанную команду в Steam → Свойства игры → Параметры запуска.
   Если Steam запрещает clipboard, выделите команду в поле панели и скопируйте вручную.
5. Начните с ×2, Performance, частоты экрана из Steam, очереди 2 и запаса +3.
   При обновлении плагина перезапустите игру один раз для загрузки новой библиотеки.
   Дальнейшие настройки применяются на лету. Встроенную генерацию игры отключите,
   чтобы один владелец управлял промежуточными кадрами.

Для проверки 45→90 используйте экран Steam 90 Гц и ограничитель исходных 45 FPS
внутри игры (для DXVK также возможен `DXVK_FRAME_RATE=45`). Ограничитель общего
вывода Gamescope/Steam должен пропускать 90 FPS: лимит 45 может ограничивать уже
всю последовательность. Плагин не меняет настройки Steam автоматически.

Для игры 582160 на стандартной установке Deck:

```sh
python3 /home/deck/.local/share/gsf-next/launch.py --appid 582160 -- %command%
```

Сначала подготовьте профиль кнопкой. Off останавливает optical flow и synthesis;
слой остаётся в подготовленной игре для включения без перезапуска. При удалении
плагина сохранённая команда становится запуском без слоя. Плагин не меняет TDP/GPU Clock, системные Vulkan
manifest-файлы и Steam launch options автоматически. Результаты сохраняются в
`~/GSF-Next-Results`; экспорт доступен из панели.

×3/×4 используют один flow на пару и несколько warp-dispatches. Выбор множителя —
верхняя граница: actual WSI ratio зависит от исходного FPS, частоты экрана,
доступных изображений и GPU. Укажите действительную частоту дисплея вручную;
после её изменения обновите профиль на лету. Automatic refresh
tracking в этой Alpha отсутствует.

`Generated` — записанные и отправленные GPU-синтезы; `WSI accepted` — принятые
Vulkan-презентации. Ни один из этих счётчиков не доказывает физический scanout.
Управляемый запуск рассчитан на SDR8; без WSI-слоя некоторые HDR-возможности могут быть недоступны. 32-bit игры не поддержаны.

Лицензии и полный соответствующий исходный код входят в ZIP. AFMF-Linux by Lain,
MIT, pinned bc56e5bd0e3a6c328aedef664d0d36363fb58b36; FidelityFX shaders retain AMD
MIT notices. Это модифицированная сборка GSF, а не официальный релиз upstream.

Сборка из приложенного SOURCE.tar.gz: `cmake -S engine/gsf-next -B build -G Ninja`,
затем `cmake --build build`. Нужны CMake ≥3.22, Vulkan headers ≥1.3.250, C11,
glslang, SPIR-V Tools, XCB и pthread. В Git checkout
`scripts/build_gsf_next.sh` дополнительно записывает commit в BUILD_INFO.json.


Alpha 4 отделяет GPU-буфер synthetic от изображений swapchain игры, использует
абсолютную временную сетку и сокращает запрос новых synthetic при уже возникшем
ожидании очереди. Это защита исходной частоты игры; невозможность выполнить
множитель остаётся видна в диагностике. Подробности и ограничения:
`docs/ALPHA4_OUTPUT.md`. Alpha 5 removes the scratch-to-output copy and includes
a measured, opt-in batched reconstruction experiment; see `docs/ALPHA5_EFFICIENCY.md`.

В панели на лету меняются ×2/×3/×4/Off, частота, качество, предел очереди и
диагностика. Качество пересоздаёт GPU-контекст на безопасной границе; один кадр
нужен для новой истории. Запас изображений и режим презентации вызывают
`OUT_OF_DATE` при следующем Acquire, до сигнализации семафора. Игра должна
поддерживать стандартное пересоздание swapchain. Панель показывает ожидание и
подтверждение из слоя. Если игра не обрабатывает OUT_OF_DATE, применяйте эти два
параметра перед запуском. Запущенная без слоя игра требует первоначального
перезапуска с командой GSF Next.

Подробная диагностика записывает локальный `present*.jsonl`: пару A/B, t,
готовность, фактическое время вызова Present и результат WSI. Отчёт не утверждает
Displayed FPS. При сравнении с обычным запуском смотрите плавность камеры и
исходный frametime, а не только Steam/MangoHud FPS.


В новой панели три основных настройки: режим, качество и частота экрана.
Статус над ними показывает ожидание, применение или работающую генерацию.
Счётчики игры и WSI выведены отдельно. Команда запуска открывается своим блоком;
очередь, запас изображений и режим вывода находятся в «Настройках вывода», а
технические значения и экспорт — в «Диагностике и отчёте».


Alpha 4 отключает WSI-слой Gamescope только внутри запускаемой игры, чтобы он не
перехватывал лишь исходные Present-вызовы выше генератора. Сам Gamescope, Steam
и Gaming Mode продолжают работать. Системные Vulkan manifest-файлы не меняются;
при удалении плагина запуск без слоя сохраняет исходное окружение.
